## 2) TODAY'S THREATS — 24 November

### A. CERT-In CIAD-2026-0062 — payment workflow abuse and agentic offensive frameworks
**Current official page: last updated 24 Nov 2026; original issue date: 20 Nov 2026. Severity: Critical.**

CERT-In reports two related but distinct patterns:

1. **Payment-workflow manipulation:** attackers alter beneficiary/business records or approval relationships, then use otherwise legitimate payment processes. A payment can pass routine checks if the underlying trusted record has been changed.
2. **AI-driven agentic offensive frameworks (AOFs):** CERT-In threat hunting identified automated reconnaissance, credential attacks, exploit preparation/modification, parallel agent/worker tasks and adaptive requests across enterprises, technology/service providers, government and academic/research institutions.

No specific actor, victim list, CVE, public IOC or transaction-loss figure is provided. Do not attribute the payment incidents to the AOF activity unless evidence links them.

**Detect:** Correlate beneficiary/bank-detail/approval changes with privileged-account activity and a subsequent payment release. For AOF activity, hunt parallel reconnaissance, unusual credential use, privilege discovery, admin-function abuse and outbound transfers.

**Remediate:** Independently verify high-risk beneficiary and approver changes; reconcile against an authoritative source outside the same provider environment; separate client environments; restrict service-provider admin access; agree log-access and notification requirements with vendors. Applicable incidents must be reported to CERT-In within six hours of noticing or being informed; unauthorised financial transactions should also be reported through the National Cyber Crime Reporting Portal or 1930.

**KQL:** Q9 is an illustrative custom PaymentAudit_CL sequence correlation. Replace event names and fields with the actual ERP/payment schema.

Source: [Official CERT-In advisory CIAD-2026-0062](https://www.cert-in.org.in/s2cMainServlet?VLCODE=CIAD-2026-0062&pageid=PUBVLNOTES02).

### B. Idunno.AntiCsrf — active exploitation of a legacy ASP.NET module
**Carry-forward; Mandiant disclosure published 18 Nov 2026, older than the 72-hour window but still urgent because exploitation is reported and no patch exists.**

Mandiant reports unauthenticated insecure deserialization in the defunct Idunno.AntiCsrf 0.9.1.0 / 0.9.1 Beta module. A single POST to an anonymously reachable ASP.NET WebForms page can reach an unkeyed ObjectStateFormatter deserialization sink and execute code in w3wp.exe. Mandiant says in-the-wild exploitation has been observed.

- **CVE:** CVE-2026-131914; CVSS 4.0 9.3 Critical.
- **Affected:** applications loading Idunno.AntiCsrf.dll and registering Idunno.AntiCsrf.AntiCsrfModule in Web.config.
- **Fix:** no upstream patch or active maintainer. Remove the module and replace it with a supported anti-CSRF implementation. If exploited, rotate Web.config/applicationHost.config secrets, including machineKey and database credentials, and inspect webroots.
- **Detection:** Mandiant recommends reviewing IIS POST requests to .aspx pages returning 302/500 with elevated cs-bytes; search Web.config and bin directories for the module. Public DLL SHA-256 values are included in Q10.
- **ATT&CK:** T1190 — Exploit Public-Facing Application.
- **Confidence:** High for Mandiant's technical advisory and exploitation observation; no public actor or victim list.

Source: [Mandiant vulnerability disclosure MNDT-2026-0048](https://github.com/mandiant/Vulnerability-Disclosures/blob/master/2026/MNDT-2026-0048.md).

<summary>Q1 — N-able Mail Assure Local Cloud: unusual private-network egress</summary>

Assumes firewall traffic is normalized into CommonSecurityLog and the Local Cloud server IP list is populated. This is not a detector for N-able Hosted Cloud.

```kql
let MailAssureServers = dynamic([]);
CommonSecurityLog
| where TimeGenerated >= ago(7d)
| where SourceIP in (MailAssureServers)
| where ipv4_is_in_range(DestinationIP, "10.0.0.0/8")
    or ipv4_is_in_range(DestinationIP, "172.16.0.0/12")
    or ipv4_is_in_range(DestinationIP, "192.168.0.0/16")
| summarize InternalDestinations=dcount(DestinationIP),
            DestinationPorts=make_set(DestinationPort, 50),
            Activities=make_set(Activity, 10)
    by SourceIP, bin(TimeGenerated, 15m)
| where InternalDestinations >= 5
| order by TimeGenerated desc
```

**Interpretation/tuning:** Hunt for unusual internal destination discovery from the Local Cloud server. A single SSRF probe may not meet the five-destination threshold; tune against normal LDAP, DNS, mail and monitoring traffic. The empty host list intentionally returns no results until populated.

<summary>Q2 — MONAI Label: path-traversal upload hunt</summary>

Assumes legacy AzureDiagnostics Application Gateway access logs with the listed fields. Confirm whether requestQuery_s is present and whether the gateway decodes URL paths.

```kql
AzureDiagnostics
| where TimeGenerated >= ago(30d)
| where Category == "ApplicationGatewayAccessLog"
| extend Request = tolower(strcat(tostring(requestUri_s), "?", tostring(requestQuery_s)))
| where httpMethod_s =~ "PUT"
| where Request contains "/datastore/image"
    or Request contains "/datastore/label"
    or Request contains "/session/"
| where Request contains "../"
    or Request contains "%2e%2e"
    or Request contains "%252e%252e"
    or Request contains "..%2f"
| project TimeGenerated, clientIP_s, httpMethod_s, requestUri_s,
          requestQuery_s, httpStatus_d, userAgent_s
| order by TimeGenerated desc
```

**Interpretation/tuning:** A matching request is a traversal attempt, not proof of successful file write or RCE. Correlate with application/host file events and process creation. Nested encodings may require normalization upstream.
