### 2.1 CISA KEV — three new additions with 30 November remediation deadline

CISA added the following vulnerabilities on 27 November based on evidence of exploitation. The due date shown in the collected KEV data is **30 November 2026**. Federal deadlines apply to FCEB agencies; all organisations should prioritize based on exposure and business impact.

- **CVE-2026-120705 — OSGeo GeoServer XML injection.** Reported exploited in the wild. Identify all GeoServer instances, confirm the affected branch and fixed build from the OSGeo advisory, patch, restrict exposed OGC services and investigate suspicious XML requests and post-exploitation activity. **Q1.**
- **CVE-2026-129243 — OSGeo GeoServer incorrect authorization.** Reported exploited in the wild and added to KEV with the same 30 November deadline. Verify affected/fixed versions with OSGeo; review authorization rules, service accounts, data access and unexpected administrative actions. **Q1.**
- **CVE-2026-136716 — Drupal Core improper check for unusual or exceptional conditions.** Drupal states this is exploited in the wild. Apply the fixed release in SA-CORE-2026-019; inspect for unauthorized administrator accounts, modified modules/themes, unexpected PHP files and web-shell behaviour. **Q1.**

**Important:** The collected CISA KEV record does not itself establish the fixed product version. Confirm the exact release against the vendor advisory before marking remediation complete.

### 2.4 nginx — critical upstream vulnerabilities and Cisco product assessment

Cisco's advisory was published at 01:34 IST on 28 November. It describes five nginx vulnerabilities that can lead to remote code execution. The upstream affected range is nginx 1.9.5 through 1.31.8, with fixes in **1.31.9 mainline** and **1.30.7 stable**. The CVEs are CVE-2026-113425, CVE-2026-121810, CVE-2026-123007, CVE-2026-123633 and CVE-2026-123634. Inventory packages, containers and embedded deployments; prioritize internet-facing reverse proxies and services using the affected HTTP/2, HTTP/3, resolver or mail-proxy modules. Cisco is still investigating which Cisco products are affected, so follow its product-specific affected/fixed release matrix rather than applying generic nginx packages to appliances. **Q3.** [Cisco PSIRT advisory](https://sec.cloudapps.cisco.com/security/center/content/CiscoSecurityAdvisory/cisco-sa-nginx-nov-2026).

### 2.6 Detection queries — complete KQL blocks for today's briefing

All queries below are **Draft / illustrative**. They have not been executed against your tenant. Confirm table availability, connector mapping, retention, field names and local baselines before enabling analytics rules. Queries are triage aids, not proof of exploitation. Where the source schema is product-specific, adapt the query to the actual parser.

<details>
<summary>Q1 — GeoServer / Drupal web-request triage</summary>

**Purpose:** Surface suspicious requests and web activity around the newly KEV-listed GeoServer and Drupal flaws.  
**Data source/table:** CommonSecurityLog from a WAF/reverse proxy, or adapt to your web-server table.  
**Schema assumptions:** Standard CEF fields are populated; product-specific URI and rule fields may be inside AdditionalExtensions.  
**Maturity:** Broad triage query, not an exploit signature.  
**Tuning notes:** Add the actual GeoServer/Drupal host inventory, URI routes, WAF rule IDs and known scanner allow-lists. Correlate hits with application and process logs.

```kql
CommonSecurityLog
| where TimeGenerated >= ago(3d)
| extend EventText = strcat(Activity, " ", RequestURL, " ", AdditionalExtensions, " ", DeviceEventClassID)
| where EventText has_any ("geoserver", "ows", "wfs", "wms", "drupal", "SA-CORE-2026-019")
| project TimeGenerated, DeviceVendor, DeviceProduct, DeviceName, SourceIP, DestinationIP, RequestURL, Activity, DeviceAction, EventText
| order by TimeGenerated desc
```

</details>

<details>
<summary>Q2 — Cacti guest access and poller process triage</summary>

**Purpose:** Review Cacti web/poller logs for guest activity, graph preference changes and suspicious command execution.  
**Data source/table:** Syslog from Cacti/Linux hosts.  
**Schema assumptions:** Cacti, web-server and poller messages are forwarded into Syslog.  
**Maturity:** Keyword-based triage; it does not detect SQL injection by itself.  
**Tuning notes:** Add known Cacti hostnames, process names and exact poller command paths. Correlate with EDR process telemetry and web access logs.

```kql
Syslog
| where TimeGenerated >= ago(3d)
| where Computer has "cacti"
| extend Message = tolower(SyslogMessage)
| where Message has_any ("poller", "graph", "guest", "cmd.php", "spine", "sql", "shell", "wget", "curl", "bash", "sh -c")
| project TimeGenerated, Computer, HostName, ProcessName, SeverityLevel, SyslogMessage
| order by TimeGenerated desc
```

</details>

<details>
<summary>Q3 — nginx software inventory and version review</summary>

**Purpose:** Identify endpoints with nginx in the software inventory for manual comparison against the fixed upstream versions.  
**Data source/table:** DeviceTvmSoftwareInventory (Microsoft Defender Vulnerability Management).  
**Schema assumptions:** Software inventory is enabled and the table includes DeviceName, SoftwareName, SoftwareVersion and SoftwareVendor.  
**Maturity:** Inventory query only; version parsing and affected-module validation must be performed separately.  
**Tuning notes:** Include container registries, appliance inventories and SBOM data; endpoint software inventory alone will miss many container and embedded deployments.

```kql
DeviceTvmSoftwareInventory
| where SoftwareName has "nginx"
| project DeviceName, SoftwareName, SoftwareVersion, SoftwareVendor
| order by SoftwareVersion asc, DeviceName asc
```

</details>

<details>
<summary>Q4 — Vinci RAT endpoint behaviour hunt</summary>

**Purpose:** Find suspicious PowerShell execution and scheduled-task persistence on endpoints; correlate matches with the Setup Assistant installation and confirmed indicators from the eSentire report.  
**Data source/table:** DeviceProcessEvents (Microsoft Defender for Endpoint).  
**Schema assumptions:** MDE process telemetry is connected; command lines are retained.  
**Maturity:** Behavioural triage; not a family-specific signature.  
**Tuning notes:** Validate parent/child process chains and signer/hash reputation. Add the reported domains to a separate DNS/proxy hunt after validating current resolution and ownership.

```kql
DeviceProcessEvents
| where Timestamp >= ago(7d)
| where FileName in~ ("powershell.exe", "pwsh.exe", "schtasks.exe", "wscript.exe", "cscript.exe")
| where ProcessCommandLine has_any ("-enc", "FromBase64String", "Register-ScheduledTask", "schtasks /create", "Set-MpPreference", "AMSI")
   or InitiatingProcessFileName has_any ("Setup Assistant.exe", "Snipping-Tool.exe")
| project Timestamp, DeviceName, AccountName, FileName, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, SHA256
| order by Timestamp desc
```

</details>

<details>
<summary>Q5 — GitHub audit and token activity review (1Password / SAP follow-up)</summary>

**Purpose:** Triage unusual GitHub organization/repository activity while investigating the reported provider incidents.  
**Data source/table:** Syslog only if GitHub audit events are exported to a syslog/SIEM parser.  
**Schema assumptions:** Audit event JSON or text is retained in SyslogMessage; a dedicated GitHub audit table is preferable.  
**Maturity:** Broad keyword triage; it is not a breach indicator.  
**Tuning notes:** Parse actor, token type, source IP, repository, action and result into structured fields. Baseline normal CI/CD and developer automation.

```kql

| where TimeGenerated >= ago(7d)
| where SyslogMessage has_any ("github", "oauth", "personal access token", "deploy key", "repository", "git clone", "workflow")
| extend Message = tolower(SyslogMessage)
| where Message has_any ("token", "oauth", "deploy_key", "public_key", "repo.download", "repo.create", "workflow", "git")
| project TimeGenerated, Computer, ProcessName, HostName, SyslogMessage
| order by TimeGenerated desc
```

</details>
