## 2) TODAY'S THREATS

### 2.1 Keycloak policy-selected OTP flow can accept a lower-assurance password SSO session

- **Date/status:** CVE-2026-135768 published 25 November 2026 at 01:42 UTC (07:12 IST); newly disclosed.
- **Impact:** A client policy that expects a high-assurance OTP flow may accept an existing password-only SSO session if the request does not explicitly demand the assurance level. An attacker who already has a user's password or session could obtain a token that claims higher assurance than was actually completed.
- **Affected products/regions:** Red Hat Build of Keycloak and Red Hat Single Sign-On 7; version ranges and fixed package builds are not yet stated in the CNA record.
- **CVE/severity/KEV:** CVE-2026-135768; CVSS 3.1 6.8 Medium; not in CISA KEV; no vendor-confirmed exploitation or public PoC identified.
- **Detect:** Compare authentication flow and token assurance claims with the actual authentication events; look for token issuance after password-only SSO where policy expected OTP.
- **Fix/contain:** Red Hat's VEX says no mitigation currently meets its supported criteria. Track the vendor erratum. As temporary risk reduction, review clients to ensure they explicitly request the required assurance level, invalidate sessions after policy changes, and require fresh MFA for sensitive operations; treat these as compensating controls, not a vendor fix.
- **KQL query ID:** Q7.
- **Confidence/attribution:** High confidence in the CNA description; no actor attribution.
- **Sources:** [Red Hat CVE record](https://access.redhat.com/security/cve/CVE-2026-135768) · [CVE record mirror with Red Hat VEX details](https://cve.circl.lu/vuln/CVE-2026-135768).

### 2.2 JaguarJack catch-admin mass-assignment issues

- **Date/status:** CVE-2026-136444 and CVE-2026-136445 published 25 November 2026; newly disclosed. A related CVE-2026-136446 also appeared in current CVE feeds, but its exact patch relationship needs separate vendor confirmation.
- **Impact:** Dynamically determined object attributes in user/role management actions may allow a low-privileged authenticated user to alter fields they should not control.
- **Affected products/regions:** JaguarJack catch-admin 5.4.0 and 5.4.1 per the CVE records.
- **CVE/severity/KEV:** CVE-2026-136444 and CVE-2026-136445; CVSS v4 5.3 Medium. Not in KEV. CVE records contain an uncorroborated statement that an exploit may be used; no independently validated public PoC or vendor-confirmed exploitation was found.
- **Detect:** Review user/role creation and update audit events for changes to privilege, role, permission, tenant or ownership attributes not present in the approved request.
- **Fix/contain:** The records reference patch commit `3ae60d57ea6840bb33456596ad799b0a39ca94a2`; verify the project release containing it before marking fixed. Restrict user/role administration to trusted administrators and review recent role changes.
- **KQL query ID:** No universal query; application audit schema is project-specific.
- **Confidence/attribution:** Medium; CNA is VulDB and NVD status is deferred. Do not treat the phrase “exploit may be used” as confirmed exploitation.
- **Sources:** [CVE-2026-136444](https://cve.circl.lu/vuln/CVE-2026-136444) · [CVE-2026-136445](https://cve.circl.lu/vuln/CVE-2026-136445) · [Referenced patch commit](https://github.com/JaguarJack/catch-admin/commit/3ae60d57ea6840bb33456596ad799b0a39ca94a2).

<details>
<summary>Q1 — VMware vCenter / ESXi authentication and admin-session triage</summary>

**Purpose:** Find suspicious vCenter/ESXi authentication and privileged-session log entries, including possible follow-on activity after CVE-2026-123890.  
**Data source/table:** `Syslog` (vCenter/ESXi logs forwarded to Sentinel).  
**Schema assumptions:** Standard Azure Monitor Syslog columns; device names include `vcenter` or `esxi`.  
**Maturity:** Draft triage query; not a CVE-specific signature.  
**Tuning notes:** Add asset inventory filters, known admin source ranges and exact vmdir/SSO event IDs from your build. Preserve logs before patching.

```kql
Syslog
| where TimeGenerated >= ago(14d)
| where Computer has_any ("vcenter", "esxi")
| where SyslogMessage has_any ("vmdir", "ssoAdmin", "administrator", "root", "Authentication succeeded", "Login")
| project TimeGenerated, Computer, HostName, ProcessName, SeverityLevel, SyslogMessage
| order by TimeGenerated desc
```

</details>
