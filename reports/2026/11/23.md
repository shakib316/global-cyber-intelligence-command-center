## 2) TODAY'S THREATS — 23 November 2026

### 1. GL.iNet routers and KVMs: cloud compromise is blocked, endpoint persistence may remain
**Date:** Vendor advisory 20 Nov; further technical reporting 22 Nov.

- **Impact:** Attackers used a vulnerability in GoodCloud remote management to install device-specific malware. GL.iNet says the cloud attack path is blocked but explicitly warns that this does not remove malware already installed. KVM compromise could expose the computers being controlled.
- **Affected products/regions:** A subset of GoodCloud-managed GL.iNet routers and remote KVM devices globally; exact affected population and model list not disclosed.
- **Detect:** Look for the vendor-listed process `crond -i /tmp/.log`; also hunt for `ni.sh`, `gl-helper`, `gb`, modified `urandom_seed`, unexpected SSH keys, cron/startup persistence, modified `netstat`, and outbound `nc` reverse shells.
- **Reported network indicators:** `170.39.226[.]219` (reverse-shell destination), `66.245.219[.]252` and `65.20.71[.]131` (malware infrastructure observed in a customer KVM log/script analysis). These are time-bound, secondary-source observations; enrich before blocking and do not treat them as vendor-confirmed universal IOCs.
- **Remediate:** Check the current model-specific firmware. BleepingComputer reports KVM guidance of 1.10.3+ for RM10/RM1/RM1V2/RM1PE/RM4PE, 1.10.3 beta+ for RM10RC and 1.8.7+ for RMQ1; verify against the live vendor support page before change. Preserve evidence, scan, reflash if needed without restoring untrusted config, rotate credentials and investigate attached KVM hosts.
- **ATT&CK (behavioural mapping):** T1059.004 Unix Shell; T1053.003 Cron. Treat these as mappings to reported behaviours, not proof of a specific actor.
- **KQL:** Q1 below. Requires Linux audit/process events and/or firewall egress logs to be forwarded; Syslog alone will not show every process or file change.
- **Confidence:** High that exploitation occurred; medium for the specific secondary-source IPs and broader infection counts.
- **Sources:** [GL.iNet](https://www.gl-inet.com/en-eu/blogs/blog/glinet-security-notice-2026-11-20) · [BleepingComputer](https://www.bleepingcomputer.com/news/security/hackers-exploit-glinet-cloud-flaw-to-infect-routers-kvm-devices/).

### 2. MONAI Label: AI agents autonomously found and exploited a zero-day
**Date:** AWS disclosure 20 Nov; MONAI Label security release 0.8.6 published 22 Nov.

- **Impact:** Amazon Threat Intelligence says the Cairn multi-agent framework mapped a medical-imaging application API, found the path traversal in about 11 minutes, wrote files outside the datastore and later used Python's `sitecustomize.py` startup import to obtain a root reverse shell. AWS observed a campaign against East Asian university infrastructure in September; this is not evidence of a new attack beginning today.
- **Affected products/versions:** MONAI Label <=0.8.5. Upgrade to 0.8.6. The 0.8.6 release also fixes a separate `PUT /session/?uncompress=true` archive/session path traversal.
- **CVE / severity:** CVE-2026-133968. GitHub Advisory Database lists Critical / CVSS 3.1 9.8; that record is marked unreviewed. The project release confirms the fix. No CISA KEV status was confirmed in this check.
- **Detect:** Proxy/WAF logs for PUT to `/datastore/image`, `/datastore/label` and `/session/` with encoded or plain `../`; inspect unexpected writes to Python startup paths, SSH `authorized_keys`, cron and application files; correlate subsequent Python process starts and outbound shells.
- **Remediate:** Upgrade to 0.8.6; enable authentication; keep the service off untrusted networks; run as an unprivileged user with datastore-only write access. If <=0.8.5 was reachable from untrusted networks, review for unexpected file changes and rebuild from trusted media/configuration where compromise is suspected.
- **ATT&CK:** T1190 Exploit Public-Facing Application; T1059.006 Python.
- **KQL:** Q2 below. This detects suspicious HTTP requests, not successful file writes or root access.
- **Attribution:** AWS assesses a Chinese-nexus actor with **moderate confidence** based on prompts, timestamps and target selection; this is not proof of state direction.
- **Confidence:** High for AWS-observed activity and the project patch; moderate for attribution.
- **Sources:** [AWS Security Blog](https://aws.amazon.com/blogs/security/chinese-nexus-actors-cairn-ai-agents-found-a-zero-day-on-their-own/) · [MONAI Label 0.8.6 release](https://github.com/Project-MONAI/MONAILabel/releases/tag/0.8.6) · [GitHub Advisory Database](https://github.com/advisories/GHSA-2f43-rwqm-6h67).

## Sentinel KQL — illustrative queries

### Q1a. GL.iNet Linux Syslog IOC / persistence hunt
**Assumptions:** Linux audit/process/file-integrity messages are forwarded into Sentinel `Syslog`; `SyslogMessage` contains the process or file event text. This is not a substitute for endpoint telemetry.

```kql
Syslog
| where TimeGenerated >= ago(14d)
| extend Msg = tolower(SyslogMessage)
| where Msg contains "crond -i /tmp/.log"
    or Msg contains "ni.sh"
    or Msg contains "gl-helper"
    or Msg contains "urandom_seed"
    or Msg contains "authorized_keys"
    or Msg contains "170.39.226.219"
    or Msg contains "66.245.219.252"
    or Msg contains "65.20.71.131"
| project TimeGenerated, Computer, HostName, HostIP, ProcessName, SyslogMessage
| order by TimeGenerated desc
```

### Q2. MONAI Label path-traversal request hunt
**Assumptions:** Azure Application Gateway access logs are in legacy `AzureDiagnostics` with `Category`, `httpMethod_s`, `requestUri_s`, `requestQuery_s`, `clientIP_s`, `httpStatus_d` and `userAgent_s`. Adapt if using WAF, NGINX, App Service or a custom table.

```kql
AzureDiagnostics
| where TimeGenerated >= ago(30d)
| where Category == "ApplicationGatewayAccessLog"
| extend Request = tolower(strcat(
    tostring(requestUri_s), "?", tostring(requestQuery_s)
))
| where httpMethod_s =~ "PUT"
| where Request contains "/datastore/image"
    or Request contains "/datastore/label"
    or Request contains "/session/"
| where Request contains "../"
    or Request contains "%2e%2e"
    or Request contains "%252e%252e"
    or Request contains "..%2f"
    or Request contains "%2e%2e%2f"
| project TimeGenerated, clientIP_s, httpMethod_s, requestUri_s,
          requestQuery_s, httpStatus_d, userAgent_s
| order by TimeGenerated desc
```

**Interpretation/tuning:** Review matching requests and surrounding sessions; 4xx responses may be blocked attempts, while 2xx alone does not prove a successful file write. URL decoding/normalisation may be needed before matching nested encodings. Add server-side file-integrity/EDR correlation for `sitecustomize.py`, cron, SSH keys and unexpected child processes. These queries are **Draft / illustrative**, not schema-checked or lab-tested.
