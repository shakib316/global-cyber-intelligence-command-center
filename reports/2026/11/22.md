## 2. Today's threats — 22 November 2026

### 1. VMware vCenter zero-day remains the top infrastructure risk
**Description:** CVE-2026-123890 allows a network-reachable attacker to bypass vCenter authentication and obtain an administrator session. Google/Mandiant described ARMORY CASTLE activity and SAML trust abuse. Attribution is an assessment, not confirmed state attribution.

- **Detect:** Look for unexpected SSO administrator sessions/accounts, abnormal vCenter directory-service access, SAML signing-key access, unusual vCenter-to-ESXi operations and unexpected data collection.
- **Remediate:** Patch to the applicable Broadcom fixed build. Restrict vCenter management interfaces (including TCP 2012) to trusted administration networks. Hunt for compromise; patching alone does not remove persistence.
- **KQL:** Use the vCenter Syslog query in section 1C as a starting point; tune against actual vCenter audit/syslog events.
- **CVE / ATT&CK:** CVE-2026-123890; relevant behaviours include Valid Accounts, Exploitation for Privilege Escalation, and forged SAML credentials. Map exact ATT&CK techniques only after confirming telemetry.

### 2. Malicious Chromium extension steals cookies and enables browser control
**Description:** Palo Alto Unit 42 reporting describes a fake “Google Chrome” extension, associated with campaign tracking CL-CRI-1192 / UNC6671, that can capture keystrokes and Microsoft/Google cookies, scan pages for QR codes and remotely control Chromium browsers through the Chrome debugger. Confidence in the campaign assessment is moderate.

- **Detect:** Identify sideloaded/unapproved extensions, Developer Mode use, unexpected extension installation, Chrome remote-debugging flags and unusual browser-to-attacker infrastructure traffic.
- **Remediate:** Remove the extension, revoke active sessions and refresh tokens where exposure is suspected, reset affected credentials, block Developer Mode sideloading through enterprise browser policy and allowlist approved extensions.
- **KQL:** Example using Defender for Endpoint process telemetry:

```kql
DeviceProcessEvents
| where Timestamp >= ago(7d)
| where FileName in~ ("chrome.exe", "msedge.exe", "brave.exe")
| where ProcessCommandLine has_any (
    "--load-extension",
    "--remote-debugging-port",
    "--remote-debugging-pipe"
)
| project Timestamp, DeviceName, AccountName, FileName,
          ProcessCommandLine, InitiatingProcessFileName
| order by Timestamp desc
```

This is a triage hunt, not a definitive malicious-extension signature. Validate browser management telemetry and command-line availability.

### 3. CISA KEV: four actively exploited vulnerabilities require urgent patch review
**Description:** CISA's 20 November update added VMware vCenter, Apache Roller, Cisco Expressway and SAP NetWeaver flaws to its Known Exploited Vulnerabilities catalogue. The US federal due date is 23 November; private organisations should use KEV status as an urgency signal, not as a legally binding deadline.

- **Detect:** Correlate CMDB/software inventory with vulnerable versions; prioritise internet-exposed assets. Look for exploitation indicators in vendor advisories and relevant application, OS and network logs.
- **Remediate:** Patch all affected instances, verify version after change, restrict exposure until patched and review logs for pre-patch compromise.
- **KQL:** Example inventory query if software inventory is onboarded to a custom table:

```kql
DeviceTvmSoftwareInventory
| where SoftwareVendor has_any ("VMware", "Apache", "Cisco", "SAP")
| project DeviceName, SoftwareVendor, SoftwareName,
          SoftwareVersion, EndOfSupportStatus
| order by SoftwareVendor asc, SoftwareName asc
```

The query identifies inventory for manual version assessment; it does not independently determine CVE exposure. Confirm exact affected versions against each vendor advisory.

### 4. Rackspace Spot incident: Kubernetes secret exposure
**Description:** Provider-disclosed access using compromised credentials created risk of Kubernetes Secrets and cluster metadata exposure.

- **Detect:** Hunt Secret reads/list operations followed by pod creation, suspicious service-account use, unusual API access and token use outside expected workloads.
- **Remediate:** Rotate secrets and dependent credentials, revoke tokens, audit RBAC, inspect new pods/jobs and validate cloud access derived from Kubernetes secrets.
- **KQL:** Use the Kubernetes audit query in section 1B.

### 5. India/APAC: payment workflow tampering and AI-assisted attacks
**Description:** CERT-In's 20 November advisory warned about manipulation of payment records/approval relationships and AI-assisted offensive automation. The concern is abuse of trusted business workflows, not only direct payment gateway compromise.

- **Detect:** Correlate vendor/bank-detail changes, approval-chain edits, payee creation and payout events. Alert on changes followed by payments, especially when different systems or identities are involved.
- **Remediate:** Require out-of-band verification for beneficiary changes, dual approval, separation of duties, transaction limits and immutable audit trails. Review service-account permissions and automation credentials.
- **KQL:** Template only; replace table and field names with your ERP/payment audit schema.

```kql
PaymentAudit_CL
| where TimeGenerated >= ago(7d)
| where Action_s has_any (
    "BeneficiaryChanged", "VendorBankChanged",
    "ApprovalChainChanged", "PaymentReleased"
)
| project TimeGenerated, User_s, Action_s, VendorId_s,
          BeneficiaryId_s, PaymentId_s, SourceIp_s
| order by TimeGenerated desc
```

This query surfaces sensitive workflow events; implement sequence correlation (change → approval → payout) after validating event semantics.
